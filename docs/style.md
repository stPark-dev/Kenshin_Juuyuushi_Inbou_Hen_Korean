# 번역 문체 지침 (D9: Dialogue Style and Script Integrity)

이름 표기는 D8과 `text/glossary.json`을 따른다. 이 문서는 대사 문체와 대본 무결성 규칙이다.

**최우선 원칙:** 인물 말투가 직역 문법보다 앞선다. 그러나 원문의 의미, 인물 관계, 극적 의도는 절대 바꾸지 않는다.

## 1. 문장부호 (런타임 확인 후 승인 조건 충족)

| 원문 | 번역 | 비고 |
|---|---|---|
| 、 | ，(U+FF0C 전각 쉼표) | ASCII `,`가 아님 |
| 。 | ．(U+FF0E 전각 마침표) | ASCII `.`가 아님 |
| ！？…… 「」 | 그대로 | |

- 조건: 게임 렌더러와 글꼴에서 인코딩·글리프 모양·폭을 확인한 뒤 전 장면에 적용한다. 확인 결과는 아래 6절에 기록한다.
- **`，` `．` `！` `？` 뒤에는 띄어쓰기를 하지 않는다**(글리프 자체 여백이 띄어쓰기 역할을 한다. 런타임 확인).
- ASCII 문자는 쓸 수 없다(ASCII 공백만 띄어쓰기 표시로 쓰고, 빌드가 `N;`로 바꾼다).

## 2. 인물 말투 (기계적 치환 금지)

| 인물 | 기준 |
|---|---|
| 켄신 | 아래 2.1 기준(D10). |
| 사노스케 | 거칠고 직설적인 반말. 지나친 현대 속어는 피한다. |
| 사이토 | 짧고 통제된, 날 선 말. 감정 표현을 최소화한다. |
| 아오시 | 간결하고 감정을 억제한다. 불필요한 말을 거의 하지 않는다. |
| 카오루·야히코 등 | 용어집과 원작 관계에 맞춰 장면 표본 검토 후 보완한다. |

### 2.1 켄신 말투 최종 기준 (D10, 사용자 확정)

| 상황 | 번역 기준 | 예시 |
|---|---|---|
| 평상시 | 부드러운 하오체 | 괜찮소？ 다친 곳은 없소？ |
| 자기소개 | 소인 + 하오체 | 소인은 히무라 켄신이라 하오． |
| 진지한 대화 | 절제된 하오체 | 소인은 두 번 다시 사람을 죽이지 않겠소． |
| 발도재의 모습 | 나 + 단호한 평서체 | 비켜라．더는 용서하지 않겠다． |
| 당황·개그 | 평소 말투 유지, 자연스럽게 | 어라？ 그게 무슨 말씀이오？ |

- `~소이다`, `~드리리다` 같은 과한 고어 어미는 쓰지 않는다.
- 발도재(인키리 발도재) 모드는 원문에서 1인칭이 `拙者`에서 `俺`로 바뀌는 대사로 판단한다.

## 3. 경칭 (문맥 우선)

| 원문 | 기본 | 예외 |
|---|---|---|
| 殿 | 공 | 시대극풍 호칭이 어울리는 화자에게 주로 쓴다 |
| さん | 씨 | 관계에 따라 님 또는 생략 |
| 君・くん | 군 | **이름 뒤 경칭일 때만.** `君`이 2인칭(너·자네)이면 그렇게 옮긴다. 전역 치환 금지 |

### 3.0 카오루 말투 (D11, 주인공 성별 분기)

| 주인공 | 호칭 | 기본 말투 | 예시 |
|---|---|---|---|
| 남성 | ^N 군 | 해체(반말) | ^N 군，어디 가는 거야？ |
| 여성 | ^N 씨 | 해요체 | ^N 씨，어디 가세요？ |

- 두 분기에서 일관되게 유지한다. 원문 두 분기의 끝맺음을 비교해 의미·감정이 달라지지 않게 검수한다.
- 예외: 화나거나 다급하면 짧은 반말·명령형이 나올 수 있다. 두 주인공 모두에게 편하게 대하는 공통 대사는 원문 분기가 허용하는 범위에서 자연스럽게. 여성 주인공에게도 지나치게 격식 있는 합쇼체는 쓰지 않는다. 남성 주인공에게 반말이어도 거만하거나 무례하게 보이지 않게 한다.
- 이는 일본어 경어법에서 나온 규칙이 아니라 패치의 캐릭터 연출 정책이다(さん이 곧 존댓말은 아님). 호칭만 보고 모든 대사의 높임을 자동으로 바꾸지 않는다.

### 3.0.1 ^N 뒤 조사

- 플레이어가 이름을 직접 입력할 수 있으므로 받침에 따라 바뀌는 조사(은/는, 이/가, 을/를, 와/과, 으로/로, 이라고)를 ^N 바로 뒤에 쓰지 않는다. 문장을 바꾸거나 받침과 무관한 형태(의, 한테, 에게, 도, 만, 호칭 붙이기 ^N 군)를 쓴다.

## 3.1 줄 나누기 (런타임 확인)

- 대화창은 한 줄 288px(글자 16px, 띄어쓰기 8px). **줄바꿈(`^c`)이 뒤따르는 줄은 272px 이하**(꽉 찬 288px 줄 뒤에 `^c`가 오면 빈 줄이 생긴다. 원문의 288px 줄 468개는 모두 문자열 마지막 줄). 마지막 줄만 288px까지.
- 일본어 원문의 줄바꿈 위치를 그대로 따르지 않는다. 문장을 자연스럽게 이어 쓰고 `^c`는 의도한 끊김(화자 뒤, 문단 구분)에만 쓴다. 나머지는 빌드 도구가 단어 경계에서 나눈다.
- 게임 자체 자동 줄바꿈은 단어 중간을 자르므로 기대지 않는다.

## 3.2 글자 수 제한과 내용 (D11)

- 칸 크기 때문에 서사적으로 중요한 정보를 삭제하지 않는다. 옮길 수 없는 문자열(참조 없음·모르는 문맥)이 칸을 넘으면 표현을 압축하되 정보는 남기고, 그래도 안 되면 보류 표시(note)를 남겨 별도 해결한다.

## 3.3 고유명사·아이템명 (D11)

- 고유명사는 한 가지 표기로 통일한다. 게임 안에서 독음이 정답으로 쓰이는 이름(예: 神爪)은 검증 전까지 임시 표기로 관리하고 혼용하지 않는다.
- 아이템명은 직역보다 한국어로 자연스러운 명칭을 우선한다(예: 草の黄 → 애기똥풀).
- 새 묶음 번역 전에 용어집에 아이템·지명·반복 용어를 먼저 정리한다(병렬 번역 시 표기가 갈리는 것을 막기 위함).

## 4. 기술 불변 조건 (언어 규칙과 별개)

- 제어 기호, 자리 표시자(`^N` 등), 대사가 아닌 스크립트 명령은 바꾸지 않는다. 순서와 인자 값도 그대로 둔다(빌드가 검사).
- 줄 앞뒤 공백은 형식이 허용하는 경우가 아니면 보존한다. 대사 줄 앞 전각 공백 들여쓰기는 원문 관례를 따른다.
- 문자열 경계와 원문 ID ↔ 번역 대응을 보존한다(`src_hash`로 원문 변경을 감지).
- 한국어 줄바꿈은 형식이 허용하는 곳(대사 본문의 `^c`)에서만 원문과 달라질 수 있다.
- 빌드 전에 줄 폭(288px 또는 원문 최대 폭), 인코딩, 넘침을 검사한다.
- 자동 처리 도구는 제어 기호 문법을 절대 바꾸지 않는다.

## 5. 진행 방식

- ZROUP00 → ZROUP40 첫 묶음에서 주요 인물별 대사 표본을 검토해 말투 기준을 잡은 뒤 대량 번역으로 넘어간다.
